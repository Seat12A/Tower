# 2026-11-11 — Lot 3 : MVP du fact-check

## Objectif

Implémenter le premier fact-check de bout en bout (lot 3 de
[factcheck/feuille-de-route.md](../factcheck/feuille-de-route.md)) pour les comptes
suivis (N3) et les demandes manuelles de l'équipe (N4) : extraction, cadrage, collecte
avec un Atlas minimal, jugement avec second avis, rédaction de la note, assemblage,
revue dans Discord, publication et lecture publique, outil d'évaluation. Session **sans
clé d'API** : modèles et sources à clé remplacés par des doublures ; seules Wikipédia et
Wikidata pouvaient être appelées pour de vrai. Session Opus 5.5 orchestrant six
sous-agents Claude Sonnet 5.5 (modèle confirmé par chacun dans son rapport).

## Réalisé

- **Phase A (contrats et prompts, Opus)** : migration `0005` (15 tables, `dossiers.content_id`,
  source d'observation `manual`) ; valeurs fermées et signatures du domaine pur
  (`core/domain/factcheck/`) ; schémas de sortie stricts par rôle
  (`core/factcheck/schemas.py`) ; constructeurs d'entrées des modèles, sans auteur ni
  niveau (`core/factcheck/inputs.py`) ; noms des files, jobs, topics et clés
  (`core/factcheck/names.py`) ; accès paresseux (`core/factcheck/runtime.py`) ; signaux de
  confiance ; lexique chargé ; codes `TWR-FCK-001..019` et `TWR-ATL-001..007` ;
  variables ; permission `factcheck:request` ; routes `translate`, `frame_reinforced`,
  `judge_reinforced`. **Les neuf prompts** (`extract`, `translate`, `frame`,
  `query_writer`, `judge`, `second_opinion`, `objection`, `writer`, `critic`), en anglais.
- **F1** : domaine pur (comparaison du second avis, escalade, confiance, indépendance par
  origine, contrôles d'E9, fidélité d'E2, passages BM25 et SimHash, datamarking, quota),
  ~235 tests.
- **F2** : Atlas (`core/adapters/knowledge/`) : Wikipédia (révision figée, risque
  d'annulation, références), Wikidata, Google Fact Check Tools, Brave, Légifrance (PISTE),
  INSEE BDM, cache `source_cache`, sélecteur, registre amorcé (55 domaines), 56 tests ;
  vérification des API dans la documentation officielle (docstrings « Verified »).
- **F3** : service `investigate` (E6 à E9, un job par étape, escalade, seconde passe,
  conservation des seuls passages cités, `run_in_memory` réutilisé par l'évaluation), cas
  d'usage `complete_investigation` / `fail_investigation`, test de confidentialité des
  entrées, 48 tests.
- **F4** : service `factcheck` (déclenchement N3, extraction avec fidélité et rejeu,
  `record_extraction`, demande manuelle N4, assemblage E10 : confiance, revérification,
  quota et tâche de vidage, ouverture du dossier ; traductions à la validation),
  fournisseur factice `TOWER_LLM_FAKE`, 59 tests.
- **F5** : cas d'usage et routes gate (brouillons, revue, demande, lecture publique),
  bot (message de brouillon, boutons persistants, fenêtre de correction, `/factcheck`,
  réconciliation au démarrage, catalogues fr/en), 91 tests.
- **F6** : `tower factcheck eval` et `tower factcheck seed-registry`, cinq cas d'exemple
  (`tests/fixtures/factcheck_eval_examples.jsonl`), 27 tests.
- **Intégration (Opus)** : correction de la règle d'indépendance (le besoin de contexte
  n'est relevé qu'en cas de rétrogradation) ; création de la note quand l'éditeur corrige
  un brouillon qui n'en avait pas (bug trouvé au smoke test) ; adaptateurs de l'Atlas
  respectant le proxy HTTPS de l'environnement ; tests d'isolation des imports étendus.
- **Documentation** : nouvelle page [fact-check.md](../fact-check.md) ; mises à jour de
  `api.md`, `events.md`, `database.md`, `auth.md`, `services.md`, `intercom.md`,
  `architecture.md`, `configuration.md`, `.env.example`, `roadmap.md`, `README.md`,
  `decisions.md`, `factcheck/feuille-de-route.md`, `factcheck/evaluation.md` (format JSONL) ;
  `errors.md` régénéré.

## Décisions

Reportées dans [decisions.md](../decisions.md) (section « Lot 3 »). Principales : rôles
distincts pour la profondeur renforcée ; un groupe par affirmation ; schémas sans
contraintes de longueur dans le JSON Schema ; passages BM25 sans embedding ;
datamarking `ˆ` et citations vérifiées sur l'original ; escalade en tour 2 avec seconde
passe en ordre inverse ; « non vérifiable » au cadrage sans brouillon en N3 ; refus jamais
convertis en verdict ; revue `endorsed`/`validated` selon `dossiers:decide` ; origines des
versions (`machine` pour tout texte non relu) ; quota avec file d'attente ; source
`manual` ; marqueur `notified_at` et réconciliation du bot.

## Vérifications

- `ruff format --check`, `ruff check`, `mypy` strict (213 fichiers) : OK.
- `pytest` : **1092 tests verts** (536 au départ), PostgreSQL 16 réel (port 5433) ; une
  base par sous-agent (`tower_test_f1` à `tower_test_f6`).
- `alembic check` OK ; `migrate --downgrade base` puis `migrate`, et `--downgrade 0004`
  puis `migrate` : OK. `docs/errors.md` à jour (test).
- **Smoke test des vrais processus** (`TOWER_LLM_FAKE=1`, gate en `TOWER_HOST=0.0.0.0`,
  hangar `ping,ingest,radar,factcheck,investigate`, faux serveur X local, `curl
  --noproxy '*'`) :
  - ajout de `@Smoke_Account` par pseudo → résolution → lecture de la timeline →
    `content.ingested` → `factcheck.extract` → `claim.extracted` +
    `investigation.requested` → `investigate.frame`, `.collect`, `.draft` →
    `investigation.completed` → `factcheck.assemble` (revérification : `GET /2/tweets/<id>`
    vu par le faux serveur) → `dossier.opened` + **`draft.ready` reçu en SSE** ;
  - revue par l'endpoint : avis favorable d'un `reviewer` (`endorsed`, dossier en revue),
    correction par un `editor` (issue et note) → `draft.reviewed` + `verdict.published` →
    `factcheck.translate` → **lecture publique** : `fr` (origine `human`, non signalée),
    `en` (traduction automatique signalée `machine_translated`), langue du post (fr) ;
    en-tête `Cache-Control: public, max-age=300` ;
  - demande manuelle `POST /v1/factcheck/requests` sur un post anglais d'un auteur non
    suivi → lecture X, ingestion `manual`, enquête **N4 renforcée** (coût 0,0086 $ factice),
    brouillon ;
  - **bot contre le vrai gate** (script, sans Discord) : réconciliation (1 brouillon affiché,
    puis 0 au second passage), rendu fr du brouillon, avis favorable (en), rejet refusé à
    un relecteur (`TWR-AUTH-005` traduit), correction validée par un éditeur, second vote
    refusé (`TWR-FCK-008`), `/factcheck` avec un lien `twitter.com`, lien invalide
    (`TWR-FCK-012`) ;
  - `tower factcheck eval` sur les 5 exemples : 5 cas, 0 erreur, coût factice 0,0198 $ ;
    **rejeu : 0,0000 $** (cache de contenu). Exactitude 20 % et abstention 100 % : sans
    sources (voir ci-dessous) le juge n'est pas appelé, chiffres sans valeur de mesure.
- **Wikipédia et Wikidata réels** : non obtenus au smoke test de bout en bout. L'IP de
  sortie partagée de l'environnement est limitée par Wikimédia (429, puis 403 « robot
  policy »), y compris pour `curl`. Deux corrections en ont découlé : les adaptateurs
  respectent désormais le proxy HTTPS, et ils demandent des réponses non compressées
  (avec `gzip`, Wikimédia répondait 403 à travers ce proxy, et 200 sans compression). Les
  appels réels faits par F2 pendant la vérification des API (recherche Wikipédia,
  révisions, risque d'annulation Lift Wing, `wbsearchentities`) ont réussi. Les enquêtes
  du smoke test ont donc tourné sans source (capturée `TWR-ATL-*`, juge non appelé).
- **RSS** (même méthode avant/après : processus lancé directement, mesure à 8 s ; « avant »
  = `main` dans un worktree, même environnement Python) :

  | Processus | Avant | Après | Cible |
  |---|---|---|---|
  | gate au repos | 84 Mo | 87 Mo (+3) | ≤ +5 Mo ✅ |
  | hangar `ping,ingest,radar` au repos | 72 Mo | 74 Mo | — |
  | hangar `ping,ingest,radar,factcheck,investigate` au repos | 72 Mo | 78 Mo (+6) | ≤ +20 Mo ✅ |
  | hangar 5 services après 3 enquêtes, revérifications et traductions (factices) | — | 95 Mo (+23) | à rapporter |
  | gate après le smoke test (≈ 30 requêtes, SSE) | — | 93 Mo | — |
  | intercom `--dry-run`, gate joignable | 78 Mo | 78 Mo (0) | ≤ +10 Mo ✅ |

  La hausse après enquête vient surtout de httpx et de son contexte TLS, des adaptateurs
  de l'Atlas et des schémas pydantic chargés au premier appel ; seul le réplica qui active
  `factcheck`/`investigate` la paie.
- Isolation des imports (tests) : gate ne charge ni `openai`, ni `anthropic`, ni les
  adaptateurs de l'Atlas, ni les services ; un hangar sans `factcheck`/`investigate` ne
  charge rien du fact-check ; un hangar avec les cinq services ne charge ni SDK, ni httpx,
  ni FastAPI, ni adaptateur avant le premier job.
- **Non vérifié** :
  - aucun appel réel aux modèles (OpenAI, Anthropic) ni aux sources à clé (Brave, Google
    Fact Check Tools, Légifrance/PISTE) : schémas, paramètres et prompts jamais confrontés
    à un vrai modèle ; la **qualité des verdicts n'est pas mesurée** ;
  - Légifrance : aucune documentation officielle de l'API n'était accessible ; corps de
    recherche et `getArticle` tirés de documentations tierces (à vérifier en premier) ;
  - la récupération des pages (références Wikipédia, résultats Brave) passe par
    `HttpFetcher`, qui se connecte à l'IP résolue sans proxy : impossible dans ce bac à
    sable, normal en production ;
  - boutons, fenêtres de saisie et messages dans un vrai serveur Discord ;
  - charge réelle (plusieurs réplicas, concurrence des étapes) ;
  - escalade et seconde passe vues seulement dans les tests (le fournisseur factice donne
    des avis concordants).

## Points ouverts / suite

- **Question à Jules** : coefficient du second avis « même côté » (+0,8 dans le tableau de
  `pipeline.md`, « sans effet » selon Q3) ; le code applique le tableau, réglable par
  `TOWER_FC_CONFIDENCE_COEFFICIENTS`.
- `RetryLater` ne consomme pas d'essai : un budget épuisé fait attendre l'enquête jusqu'à
  la période suivante ; le repli « brouillon incomplet » ne joue qu'après des échecs d'une
  autre nature. À confirmer.
- Une nouvelle demande `/factcheck` d'un post déjà traité est acceptée (le job précédent
  est terminé) et ne relance rien (affirmations et enquête N4 déjà présentes) ; le bot
  affiche « demandée » au lieu de « déjà traitée ».
- Un dossier qui regrouperait plusieurs brouillons (lot 4) ne suit que la première décision.
- Le token du bot doit inclure `factcheck:request` ([intercom.md](../intercom.md)).
- **Session de validation et de réglage** : clés Anthropic, OpenAI (organisation avec
  partage), Brave, Google, PISTE (bac à sable puis production) et éventuellement INSEE ;
  au moins 50 affirmations du jeu de référence au format de
  [factcheck/evaluation.md](../factcheck/evaluation.md#format-du-jeu-et-commande) ;
  `tower factcheck eval`, réglage des prompts, coefficients et seuils ; premier appel réel
