## Pure domain (`core/domain/factcheck/batching.py`)
- `INJECTION_MARKERS`: casefolded patterns of known prompt-injection phrases (English and
  French at least: "ignore previous instructions", "ignore les instructions", "system
  prompt", "you are now", "tu es maintenant", "</input>", "<input", "assistant:",
  "developer message"…) and `has_injection_marker(text) -> bool`.
- `estimate_tokens(text) -> int` (`ceil(len/3)`).
- `compose(candidates: Sequence[BatchCandidate], *, size: int, max_tokens: int,
  dissimilarity: float) -> list[list[int]]` where `BatchCandidate(content_id, tokens,
  vector: Sequence[float] | None, narrative_id: int | None, solo: bool)`: greedy, oldest
  first; a batch never holds two posts with cosine > `dissimilarity` nor two posts of
  the same narrative; never more than `size` posts (hard cap 12) nor `max_tokens`
  (a single post above the limit goes alone); `solo` candidates (injection markers) are
  alone. Deterministic.
- `ready(batch_ids, *, oldest_age_s: float, size: int, max_wait_s: float) -> bool`
  (full, or the oldest waited long enough).
- `canary_post(seed: int) -> tuple[str, str]`: a synthetic French post with a unique
  figure, returns (text, token); `canary_contaminated(token, claims_by_post) -> bool`
  (the token appears in a claim of another post).
- `audit_positions(batch_size, rate, rng) -> list[int]`: positions to replay solo,
  stratified by position (each position has the same probability `rate`).

## Batch composer (`compose_batches`, periodic, 60 s)
If `settings.fc_mass_flow` is false: return 0. Select up to 500 pending contents
(CONTRACT5 decision 1) oldest first with their E1 vector and text length; call
`narratives.filter_for_surges(session, settings, ids)` (import lazily inside the
function: `from tower.services.factcheck import narratives`) and write
`content_extractions(status='sampled_out', narrative_id)` for the returned map; compose
the rest; for each batch that is `ready`, enqueue `factcheck.extract_batch` (queue
`fc-bulk`, payload `{"content_ids": [...]}`, `dedupe_key=extract_batch_key(ids,
prompt_version)` where the prompt version comes from `PromptRegistry.default()` for
`extract_batch`). A content is in at most one pending job (dedupe on the batch is enough
because composition is deterministic; also skip contents already in a queued/running
`factcheck.extract_batch` job payload — use a SQL check on `jobs.payload`).

## Batch job (`extract_batch`)
- Load the contents (skip those now extracted). One `extraction_batches` row
  (`status='pending'`, ids, canary token when `rng.random() < fc_canary_rate`).
- Input: `extract_batch_input` with one `extract_input(...)["post"]` per content (ids are
  the content ids as strings; the canary gets id `canary-<batch id>`); call the router
  with role `extract_batch`, schema `ExtractBatchOutput`, level `N1`, budget scope
  `level:N1` (see how `_run_extract` builds requests). `BudgetExhausted` ⇒ `RetryLater`.
- Missing ids ⇒ capture `TWR-FCK-039` and those posts are replayed alone (enqueue the
  existing `factcheck.extract` job at level N1? NO: N1 solo replays run inside this job
  with role `extract` one by one). Unknown ids are ignored.
- Fidelity per post with the existing `_faithful` logic: an unfaithful claim is dropped and
  the post replayed alone; **≥ 2 fidelity failures in the batch or canary contamination ⇒
  the whole batch is replayed solo** (status `replayed_solo`, `contamination=true` and
  capture `TWR-FCK-040` for a canary). The canary's own claims are never recorded.
- Solo audit: for `audit_positions(...)` posts, replay alone with role `extract` and write
  an `extraction_audits` row (claims counts, discordant when counts or figures differ);
  the batch result is kept (the solo replay is not ground truth).
- Recording: for each post, E3 `match_claims` then `record_extraction(..., level='N1',
  investigate=False, matches=...)` and `content_extractions` (`extracted`/`no_claim`,
  `batch_id`, `position`), one transaction per post. Batch row `done` with cost.
- Idempotent: rerunning a finished batch does nothing (contents already extracted).

## `record_extraction(..., investigate: bool = True)`
When False: groups are created `dormant`, no `request_investigation`, no band
inheritance change (band inheritance still applies: a covered variant is covered), a
joined claim never triggers an investigation (except the N4 path which cannot happen
with N1). Also upsert `content_extractions` (`extracted`) for the content (level, no
batch) unless the caller passes `extraction_status=None`; solo `extract` job writes
`no_claim` when no claim was found.
