## Batch evaluation (`tower factcheck eval --set … --batch [--batch-size 10]`)
For the cases' `post_text` (or `claim`): compose batches with the production composer
logic (pure `compose`, vectors from `runtime.get_embedder`), insert a canary per batch,
run role `extract_batch` and, for every post, role `extract` alone (cache makes replays
free); report: contamination rate (canary or figures of another post found in a post's
claims), omission rate (solo finds a claim with a figure the batch result misses),
per-position omission, claims count delta, cost per post (batch vs solo). No DB write
except caches. Deterministic with `TOWER_LLM_FAKE=1` (contamination 0).

## Load test script (`scripts/loadtest_wave.py`)
Against running processes (gate URL, service token, installation tokens generated
locally), arguments `--posts`, `--minutes`, `--narrative-variants`, `--watched-post-every`:
- generates a synthetic wave: variants of one French rumour (copies, near copies, a few
  new figures, translations with the `[fr: …]` marker), spread over many fake authors and
  installations, posted through `POST /v1/ingest/observations` (batches of 50, respecting
  the per-installation quota by using many installation tokens), plus background posts
  of unrelated topics, plus regular posts of a watched account through the fake X server
  used in the smoke tests (or directly as a radar service token ingestion: document it);
- measures and prints: ingestion throughput, `content.ingested` → `draft.ready` delay of
  the watched (N3) posts during the wave (p50, p95), queue backlog per queue over time
  (SQL on `jobs`), narrative state transitions and the time of the first surge draft,
  sampled-out share, model and embedding cost per post (`llm_calls`) and budget counters
  (no scope above its cap);
- SQL through psycopg-free code: use `asyncpg` (already a dependency) or the project's
  `Database`.
Document how to run it locally (`TOWER_LLM_FAKE=1`, gate on `0.0.0.0`, hangar with the
fact-check services) in `docs/development.md`.
