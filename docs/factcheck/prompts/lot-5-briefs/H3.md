## Scheduler (`schedule`, periodic singleton, every 60 s)
- Read the last `scheduler_runs.started_at`; rate = contents first seen in the last hour;
  if `now - last < interval_s(...)`: return 0. Else one pass (insert the run row first).
- Step 1, metrics (SQL aggregates only, no row loading of observations): for active
  groups (not merged, not passive, activity within 48 h): `observers_6h` (distinct
  non-null `installation_pseudonym` of observations of the group's contents in 6 h),
  velocity (observations last hour ÷ previous hour, 0 if fewer than 10), views (max of
  the contents' `metrics->>'impression_count'` / `views`), `reach` updated.
- Step 2, promotions/demotions (CONTRACT5 decision 5): enqueue
  `factcheck.promotion_check` (`dedupe_key=promotion_key(group, hour)`) for N1 groups
  with reasons; demote due N2 groups (use case). `promotion_check` job: platform client
  (`runtime.get_platform_client`) `get_metrics` on the representative content, cost
  reserved on `provider:x` like the lot 3 recheck; confirmed (any reason still holds with
  the fresh metrics, or the reason was not metric-based) ⇒ raise to N2 (use case, event
  reason `promotion`); unavailable platform ⇒ promote with `flags.unconfirmed`; failure ⇒
  `TWR-FCK-042` info, no promotion.
- Step 3, `await narratives.waves_step(session, settings, now)` (lazy import of
  `tower.services.factcheck.narratives`; the stub returns `{}` until H4 lands; store its
  dict in the run stats).
- Step 4, priority of every candidate group (N1 dormant new since the last pass, N2
  dormant/queued without investigation), written in `claim_groups.priority`.
- Step 5, enqueue in priority order: N2 ⇒ `request_investigation` (level N2, standard
  depth, flags `{"scheduled": true}`) while `level:N2` budget remains (remaining cap of the
  current period ≥ the level's mean investigation cost), the daily draft quota is not
  reached (`today_count` of the assembly module vs the active profile quota) and the
  number of queued+running jobs in `fc-deep` < `fc_deep_queue_capacity` (else log
  `TWR-FCK-045` once per pass, stats `held_back`); N1 ⇒ `factcheck.light_check` for the
  top `fc_light_check_share` of new dormant groups (`dedupe_key=light_check_key(group,
  profile.version)`). Groups of a narrative in surge/alert are handled by H4's
  `waves_step` (skip them here).
- Passive: groups whose active verdict is older than 48 h ⇒ state `passive` (use case,
  no event).
- Finish the run row (stats: rate, interval, promotions, demotions, enqueued,
  held_back, waves).

## Light check (`light_check` job)
Payload `{"group_id": int, "dossier_investigation_id": int | null}`. CONTRACT5 decision
7: band path (no model) or evidence path: validated facts (`references.resolve_fact`),
Atlas with `fact_checks_only=False`, `skip_encyclopedia=True`, `max_web_searches=0`,
documents → evidence items (`id` E1…, kind, source domain, text truncated 600 chars,
datamarked), or the kept passages of the given dossier investigation (`evidence_passages`
with `kept=true` or text not null) when `dossier_investigation_id` is set. Role
`light_check`, level of the group, schema `LightCheckOutput`. No evidence at all ⇒
`uncertain` without a model call. Write via a use case (`light_signal`,
`light_checked_at`, `light_evidence` = `{explanation, evidence: [{id, kind, source}]}`).
Failure ⇒ `TWR-FCK-041`. Idempotent per (group, profile version).
